1. PROJECT SETUP & PREREQUISITES
1.1 Required Accounts & API Keys
Before writing any code, you must obtain:

News API Account

Sign up at newsapi.org
Get your API key (free tier provides 100 requests/day)
Document the rate limits (requests per minute/day)
Note: Free tier only provides articles from the last 30 days


Google Gemini API

Sign up at ai.google.dev
Get API key from Google AI Studio
Recommended model: gemini-1.5-flash (cheaper, faster for extraction tasks)
Free tier: 15 requests per minute, 1500 requests per day
Document the rate limits


MongoDB Atlas (free tier)

Sign up at mongodb.com/cloud/atlas
Create a free M0 cluster
Create a database user with read/write permissions
Get connection string
Whitelist your IP address (or use 0.0.0.0/0 for development)

1.3 Technology Stack & Rationale
Core Technologies:

Python 3.12 - Latest stable version
MongoDB - Document store for articles (flexible schema, good for text)
NetworkX - For in-memory graph operations and analytics
Streamlit - Frontend framework (rapid development, Python-native)
Google Gemini API - LLM for entity extraction
NLTK - Text preprocessing

For Graph Visualization - CRITICAL DECISION:
I recommend PyVis over other options. Here's why:
Option 1: PyVis (RECOMMENDED)

Built specifically for NetworkX integration
Creates interactive HTML visualizations
Easy physics simulation for graph layout
Click/hover interactions built-in
Integrates seamlessly with Streamlit using components.html()
Can handle 100-1000 nodes comfortably
Very simple API

Option 2: Plotly (Alternative)

More customizable
Better for very large graphs (1000+ nodes)
More complex API
Good Streamlit integration

Option 3: Cytoscape.js via Streamlit-Agraph

Most powerful for complex layouts
Steeper learning curve
Better for production-scale applications

My Recommendation: Start with PyVis, migrate to Plotly if you need more scale.

NetworkX is simpler for this project size
No need for separate database server
All Python, easier to learn
Graph analytics (PageRank, community detection) are built-in
Can serialize to disk easily
For production scale, you can migrate to Neo4j later
